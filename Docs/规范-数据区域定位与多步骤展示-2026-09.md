# 开发规范：统一数据区域定位 与 多步骤详情展示

> 版本：2026-09　|　适用范围：Excel AI 插件所有「读 Excel 数据」「执行确定性技能」的流水线
> 来源：2026-09 一轮 bug 排查与重构的沉淀，作为后续开发必须遵守的规范（非建议）。

---

## 1. 统一数据区域定位（三级优先，一工具）

**必须**：所有需要读 Excel 数据的任务，区域确定必须收敛到单一入口 `excel_read_range`，按下述三级优先级确定目标区域：

1. **显式区域**：用户输入写死的区域，用 `parseExplicitRange` 软编码解析（如 `A5:F40` / `$B$2:$D$10` / 单格 `A1`），**最高优先**，不被选区/自动探测覆盖。
2. **用户选区**：已框选的数据区域（多格），其次优先。
3. **自动探测**：未显式指定且无清晰选区（未框选 / 仅单格）时，用 `autoProbe` → `UsedRange` 探测整表数据区。

**反例（禁止）**：为某个任务单独硬编码区域解析、或绕过该优先级在多个调用点各写一套取数逻辑。

## 2. 覆盖范围：所有读 Excel 数据的确定性任务

**必须**：美化 `Beautifier` / 格式 `Formatter` / 图表 `Chart`（智能图表向导）/ 清洗 `Cleaner` / `CRUD` 等所有读 Excel 数据的确定性技能，在「未显式写死区域 && 未框选/仅单格」时**都要**自动探测整表数据区。

- 前端在 `executeSkillSpecMode` 开头统一调用 `detectDataSelection`，回填 `ctx.selection`；探测成功即以探测结果为唯一数据区，不再重复探测。
- **禁止用 `!isChart` 之类排除图表**：图表与美化/格式一样无预置读取步骤，必须纳入同一前端开头探测，否则未框选时图表会报「未指定图表数据范围」。
- 清洗例外：其「读取数据」步骤兼任探测，前端开头不重复探测（保持每次只调一次 `excel_read_range`，不产生重复读取）。

## 3. 后端 `autoProbe` 双分支回退（关键根因）

**必须**：后端 `excel_read_range`（`ExcelMcpTools.Core.vb` 的 `ExecuteReadRange`）的 `autoProbe` 必须在**两个分支**都回退 `UsedRange`：

- 分支 A：`rangeAddr` 为空（活动单元格分支，已有）；
- 分支 B：`rangeAddr` 为单格 / 被选区注入的分支（本次新增）。

**根因**：Skill 前端发出的"无 range 自动探测"请求，会被 **MCP 中间件强制注入活动单元格**（如 `H24`）为 `range`。若后端只在 `range` 为空时回退，就会读到**空单格** → `raw=[]` → 前端识别 0 行 → `detectDataSelection` 返回 null → 上游报「未检测到选区 / 未指定图表数据范围」。

即：**MCP 注入活动单格是"无 range 自动探测"的通用障碍**，凡读数据任务的自动探测，后端都必须在各 range 分支对单格做 UsedRange 回退。

## 4. 去重默认高亮（安全优先）

**必须**：智能数据清洗的去重（`removeDuplicates`）在用户措辞含糊（未明说"删除/高亮"）时，默认 `markDuplicate = true` —— **仅高亮标记重复行，不直接删行**。

- 用户明确说「删除重复 / 去重（真删）」→ 真删；
- 用户明确说「高亮重复」→ 高亮；
- 含糊措辞 → **默认高亮**（安全优先，避免误删数据）。

## 5. 多步骤详情展示规范

步骤面板「展开无操作 / 无详情」是**多点复合问题**，必须全部满足：

1. `ProgressTracker.init` 必须做**内容级比较**（`status`/`detail`/`toolName`/`params`），不能仅比步骤数，否则新详情不渲染；
2. 步骤归一化必须**保留 `toolName` / `params` / `result`**，不得丢弃真实工具信息；
3. `renderSkillSteps` 必须**透传 `subSteps`**（清洗等"外壳+子步骤"结构），并在 `buildPlanHtml` 渲染子步骤的真实工具行；
4. 末步详情合并**只能合并该步自身 `realSteps`**，排除 `execResult.result.message` 等**整体累计摘要**，避免某一步展开显示"所有步骤的动作"。

## 6. 前后端分离与前端缓存铁律

| 层 | 改动位置 | 生效方式 |
|---|---|---|
| 前端区域定位（三级优先、`detectDataSelection`、`parseExplicitRange`） | `UI/js/chat-v2/pipelines/skill-pipeline.js` 等 | **重启 Excel 即生效** |
| 后端 `autoProbe` 回退 | `Services/Mcp/ExcelMcpTools.Core.vb` | **必须重新编译 dll** 才生效 |

**必须**：
1. **改前端源码后必须 bump `index.html` 里脚本的 `?v=` 版本戳 + 同步 `bin/Debug`**。WebView 对同名版本号强缓存，只 copy JS 不够，会表现为"改了但行为没变"（以下次 `index.html?v=` / `skill-pipeline.js?v=` 平台日志核对实际加载）。
2. 后端 `.vb` 改动必须重编译；**缺编译时前端 `detectDataSelection` 会静默返回 null**，易误判为前端逻辑问题——排查时先确认 dll 编译时间 ≥ `.vb` 修改时间。

## 7. 实现位置速查

- 前端三级优先 & 自动探测：`skill-pipeline.js` → `parseExplicitRange`、`detectDataSelection`、`executeSkillSpecMode` 开头探测块、清洗「读取数据」步骤、`executeCleanSingleOp`/`buildBeautifyOps`。
- 后端单格探测回退：`ExcelMcpTools.Core.vb` → `ExecuteReadRange` 的「指定范围」分支。
- 去重默认高亮：`skill-pipeline.js` → 清洗 `markDuplicate` 默认值分支。
- 步骤详情展示：`skill-pipeline.js`（归一化/renderSkillSteps/末步合并）+ `ProgressTracker.js`（init 内容级比较、buildPlanHtml 渲染工具行/子步骤）+ `chat-v2.css`（`plan-step-tool` 等样式）。
