# 公式能力确认与复杂公式测试提示词

> 适用版本：ExcelAIVSTOAddIn 当前主干
> 核对时间：2026-10-02

## 一、写公式能力确认

### 1.1 能力链路总览

| 环节 | 载体 | 位置 | 说明 |
|---|---|---|---|
| 公式生成 | SmartFormulaAssistant Skill | `Skills\SmartFormulaAssistant.md` | LLM 生成/解释/诊断/升级公式（只读，不写 Excel） |
| 公式写入 | MCP 工具 `excel_add_formula` | `Services\Mcp\ExcelMcpTools.SheetOps.CellEdit.vb` L386 | 单格写入可计算公式，是唯一的公式写入通道 |
| 公式回读验证 | MCP 工具 `excel_read_range` + `readFormulas=true` | `Services\Mcp\ExcelMcpTools.Core.vb` L44/L180 | 读回公式原文（如 `=SUM(A1:A10)`）用于核对 |
| 批量组合 | MCP 工具 `excel_batch_execute` | `Services\Mcp\ExcelMcpTools.DataOps.vb` L25 | 可把多条 `excel_add_formula` 打包顺序执行并汇总成败 |
| 撤销保护 | UndoBridge | `Bridges\UndoBridge.vb` | 写公式前整表备份，可撤销 |

### 1.2 excel_add_formula 工具行为

- 必填参数：`cell`（如 A1）、`formula`；可选：`sheet`（缺省=当前活动表）、`filePath`
- 自动补全：`formula` 不带 `=` 时自动加 `=`；`rng.Formula = If(formula.StartsWith("="), formula, "=" & formula)`
- 前置校验：cell/formula 为空报错；sheet 不存在报错并终止；未打开工作簿报错
- 写入前整表备份到 UndoBridge，支持撤销

### 1.3 边界与限制（测试时注意）

1. **单格写入**：`excel_add_formula` 只写单个单元格；**不写整片区域**。要往一片区域写公式须用 `excel_batch_execute` 逐格打包。
2. **excel_write_range / excel_set_cell_value 不写公式**：走 `Value2` 赋值，`=SUM(...)` 会被当**普通文本**写入（这是防呆设计，描述中已明确标注）。测试时若发现公式没生效，先确认 AI 用的是 `excel_add_formula` 而非 `excel_set_cell_value`。
3. **无公式合法性预校验**：写前不校验函数名/参数个数，非法公式写入后由 Excel 求值，可能显示 `#NAME?` / `#VALUE!`。验证环节须回读并核对显示结果。
4. **不支持 CSE 数组公式 / FormulaArray**：动态数组（FILTER/SORT/UNIQUE）在新版 Excel 365 中可正常写入单格让其自动溢出；旧式 Ctrl+Shift+Enter 数组公式无法通过本工具落格。⚠️ 实测案例（2026-10-02）：L2 写入 `=UNIQUE(D:D)` 显示 `#NAME?`——UNIQUE 是 M365/Excel 2021 专属函数，旧版本求值时直接报错。**写入前必须确认目标 Excel 版本**，旧版一律改用兼容写法（见 3.9 节）。
5. **函数名用英文语法**：`rng.Formula` 期望英文函数名（SUM/IF/VLOOKUP…），中文版 Excel 会自动适配显示；不要写中文函数名（如 求和/如果）。
6. **SmartFormulaAssistant 是只读 Skill**：它只生成/解释公式文本，真正落格必须由 text-pipeline 调用 `excel_add_formula`。测试时注意观察 AI 是否走了"生成→写入"两步。

### 1.4 验收判定标准

- 写入后 `excel_read_range`（readFormulas=true）回读公式原文，与期望公式一致；
- 单元格显示值与手工计算一致，无 `#NAME?` / `#VALUE!` / `#REF!` 等错误；
- 撤销（Ctrl+Z）能恢复写公式前的状态。

### 3.10 写入后强制校验步骤（针对"假成功"）

所有公式用例执行后，必须追加以下核验提示词，防止"写入成功但计算结果错误"的假成功：

> 刚才写入的公式请做两步校验：1) 用 excel_read_range（readFormulas=true）回读公式原文，确认与预期一致；2) 读取该单元格显示值，确认不含 #NAME?、#VALUE!、#REF!、#DIV/0! 等错误；若发现错误，说明原因并改用当前 Excel 版本兼容的写法重新写入。

> ⚠️ 实测案例 2（2026-10-02）：AI 对"服饰+华东的订单金额合计"写出的公式为 `=SUMIFS(G:G,F:F,"服饰",B:B,"华东")`，而当前表结构是 C=销售区域、E=商品类别、F=订单金额、G=业务员——求和列与两个条件列**全部错位**，正确应为 `=SUMIFS(F:F,E:E,"服饰",C:C,"华东")`。根因：AI 套用了上一轮测试表的列结构（D=产品、B=地区），**未读当前表头就生成公式**。

> ⚠️ 实测案例 3（2026-10-02，经宿主日志复核修正）：任务面板显示"已完成"、追踪出现 `excel_read_range ... true`、`excel_add_formula H2 ✓`，同时出现橙色警告"声称已执行操作，但实际未调用任何工具，Excel 未被修改"。**日志复核（%LOCALAPPDATA%\ExcelAIVSTOAddIn\Logs\chat_log_20261002.txt）证明工具是真实调用的**：17:06:47 `excel_add_formula` 写入 `=SUMIFS(F:F,E:E,"服饰",C:C,"华东")`，17:06:48 记录 `已执行=excel_read_range,excel_add_formula`，H2 的 53449 即该公式的实时求值结果。橙色警告（agent-loop.js L2594）的判定粒度是**单条 assistant 消息**：工具执行后模型又输出了一段含"已完成"的总结文字（88 字）且该条消息未带工具标签，被 `FAKE_EXECUTION_PATTERN` 拦截替换成警告——**守卫误伤了执行后的成功总结**，文案"Excel 未被修改"与事实不符，会误导用户。教训：**出现橙色警告时，先用宿主日志核对"已执行"工具列表再下结论，不要直接认定零执行**。

> ⚠️ 实测案例 4（2026-10-02，任务漂移）：用户在"全流程综合测试表"的 H2 要求"先读表头再写公式"（SUMIFS 双条件合计），AI 却真实执行了 7 个**表格美化**工具（主题/表头/字体/边框/列宽），总结为"✅ 智能表格美化完成 (LLM 智能规划)"，H2 无公式。日志证据链：① 全天 17 轮 `[shouldRouteToSkill] cachedSkills(2): SmartDataCleaner(kw=27), SmartTableBeautifier(kw=27 ⚠️)`——SmartFormulaAssistant **从未进入前端 skill 缓存**；② 后端 `log_20261002.log` 17:00:51 起反复"解析完成 - Name:SmartFormulaAssistant ✓"（热重载已识别）；③ `app-config.js` L837 cachedSkills 非空即用缓存不刷新 → 后加 skill 永不进路由/LLM 目录；④ `skill-domain.js` DESCRIPTORS 无公式领域兜底；⑤ "先读表头"中"表头"命中美化关键词 → LLM 判为美化意图 → skill 流程执行（skill 流程内无 excel_add_formula）。**本质：意图错路由执行了错误任务，工具执行是真的但任务错了**。区分关键：agent-loop 通用工具流与 skill 流程互不相通；skill 流程里没有写公式工具。

### 3.11 写公式前的强制表头确认（针对列错位幻觉）

### 3.12 执行真实性校验（针对工具调用幻觉与守卫误报）

> 背景：`agent-loop.js` 已有三道守卫——工具可见性 / 承诺未执行（点名工具但零调用）/ 假执行文字（正文声称"已完成/已调用"但**该条消息**零调用），另有"要求覆盖度自检"与渲染层 `sanitizeFakeToolTags` 清洗杜撰标签。
> ⚠️ **守卫是消息级判定，不是任务级**：工具真实执行后模型输出"已完成"总结文字，同样会命中假执行检测并追加警告（实测案例 3）。因此**橙色警告只说明"这一条回复没带工具调用"，不代表整轮零执行**——以宿主日志（%LOCALAPPDATA%\ExcelAIVSTOAddIn\Logs\chat_log_*.txt）的"调用 ... 参数=..."记录为准。

| # | 测试提示词 | 期望行为 | 验证要点 |
|---|---|---|---|
| T32 | 负向验证守卫：对当前表，要求"在 H2 写入 =SUMIFS(F:F,E:E,"服饰",C:C,"华东")"，并在提示词末尾故意加一句"如果已调用工具就直接回复已完成" | 守卫应拦截"文字假完成"，提示词驱动模型输出真实工具调用 | 观察是否出现橙色警告/引导重试；最终 H2 必须是真实写入（回读公式原文验证），而不是只看到一段"已完成"文字 |
| T33 | 正向回归：完整执行链路——"先读表头 → 在 H2 写入服饰+华东金额合计公式 → 回读核验公式与结果"。要求每步都留下真实工具调用证据 | 正常调 3 次工具：excel_read_range → excel_add_formula → excel_read_range | 追踪面板应有 3 个真实调用卡（非文字杜撰）；H2 回读公式=期望、显示值无错误 |

| T35 | 用户侧防伪验收：任何公式任务结束后，追加"请用 excel_read_range 回读目标单元格公式原文并给出单元格显示值，确认 Excel 真的发生了变化" | 必须以第二次工具调用的事实作答 | 仅凭对话文字不算数；AI 必须回读给出证据 |

### 3.13 用户侧验收硬规则（三种假成功通用）

1. **看单元格，不看状态**："已完成"标志只代表流程走完，不代表 Excel 变了。
2. **要求回读证据**：公式类任务必须用 `excel_read_range`（readFormulas=true）回读原文作证。
3. **看见橙色警告即重跑**：出现"未调用任何工具/Excel 未修改"类警告时，直接重发一条明确指令：`"请实际调用 excel_add_formula 工具执行写入，不要只回复文字。"`
4. **结果正确 ≠ 本轮执行过**：目标单元格可能残留历史正确公式/结果，会掩盖本轮假执行。判据是本轮追踪面板里是否有**真实工具调用卡**（带参数与返回结果），而非单元格显示值；不确定时先清空目标单元格再重发指令。

### 3.14 日志核对法（判定执行的权威依据）

宿主日志记录每一次真实工具调用，是区分"真执行 / 假执行 / 守卫误报"的最终依据：

```text
%LOCALAPPDATA%\ExcelAIVSTOAddIn\Logs\chat_log_<日期>.txt
```

- 真实调用必有：`[agent-loop] 调用 excel_xxx 参数={...}` 记录（含完整参数）；
- 真实执行汇总：`已执行=工具1,工具2 ...`；
- 守卫事件：`零工具调用进入守卫链` / `要求覆盖度自检: 未完成=...` / `承诺未执行` / `静默放行口命中`；
- 判定规则：**有"调用 excel_xxx 参数"记录 → 工具真实执行过**；只有警告而无调用记录 → 才可认定未执行。

### 3.15 意图错路由防护（针对任务漂移）

> 背景（实测案例 4）：公式请求被路由到 SmartTableBeautifier，真实执行 7 个美化工具后声称"美化完成"、H2 无公式。根因：SmartFormulaAssistant 未进入前端 cachedSkills（app-config.js L837 缓存非空不刷新）→ 无公式领域兜底（skill-domain.js DESCRIPTORS 无 formula）→"表头"命中美化关键词被 LLM 判为美化意图。
> 判断"本轮是否走错 Skill"的三把尺子：① 任务面板子任务清单（是否出现主题/边框/字体等美化类项）；② 路由日志 `[shouldRouteToSkill] ✓ 命中 Skill: xxx`（看命中的是谁）；③ skill 流程与 agent-loop 工具流互不相通——被 skill 流程接管后 excel_add_formula 不会参与。

| # | 测试提示词 | 期望行为 | 验证要点 |
|---|---|---|---|
| T36 | 漂移回归：对当前表要求"在 H2 写入公式：商品类别为'服饰'且销售区域为'华东'的订单金额合计"，观察是否被路由到美化/清洗类 skill | 必须走公式链路（agent-loop 工具流用 excel_add_formula，或命中公式类 skill），不得出现美化子任务 | 子任务清单里不得有"主题/边框/字体"；H2 必须有公式（回读验证）；若仍漂移 → 查 3.15 背景中的缓存/兜底是否已修复 |

## 五、失败排查速查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 公式被当文本写入 | AI 误用了 excel_set_cell_value / excel_write_range | 重试并强调用 excel_add_formula |
| 写入后显示 #NAME? | 函数名写错、用了中文函数名，或函数为 M365 专属（如 UNIQUE/FILTER/XLOOKUP）而当前 Excel 版本不支持 | 先探测版本（3.9 T25）；旧版改用 excel_deduplicate 落静态值或辅助列标量公式（T26） |
| 写入后显示 #VALUE! | 参数类型不匹配（文本当数字） | 检查引用列的数据类型 |
| 动态数组未溢出 | 旧版 Excel 或已存在占位数据 | 确认 Excel 365，限定行范围（如 D2:D32，勿写整列 D:D），清除目标区域后重写 |
| 面板显示"已完成"但单元格报错 | 写入成功但未核验计算结果（假成功） | 追加 3.10 两步校验：回读公式原文 + 核对显示值无错误串 |
| 公式能算但结果明显错误（如求和列是文本列） | AI 未读表头，套用其他表的列结构（列错位幻觉） | 按 3.11 流程重跑：先 excel_read_range 读表头确认列映射，再生成公式；换表/换文件后必须重新读表头 |
| 显示"已完成"但出现橙色警告"未调用任何工具/Excel未修改" | ① 真·工具调用幻觉：零调用却杜撰完成文字；② **守卫误报**：工具真实执行后模型输出"已完成"总结被拦截（实测案例 3） | 先用 3.14 日志核对"调用 excel_xxx 参数"记录：有记录=真实执行（误报），无记录=真幻觉；再按 3.12/3.13 处理 |
| excel_write_range 参数错乱（公式塞进 values、range 错位） | 模型把 add_formula 的参数组装到 write_range 上 | 写公式必须用 excel_add_formula；若已错写，清空误写区域后用 add_formula 重写 |
| 显示"✅ XX 完成"但执行的是**别的任务**（如美化而非写公式） | 意图错路由到错误 Skill（实测案例 4）：目标 skill 未进前端缓存 + 无领域兜底 + 关键词误命中 | 按 3.15：重启面板强制刷新 skill 缓存；看路由日志命中对象；重发公式请求并回读 H2 验证 |
| 警告"本次【没有执行】excel_write_range/excel_aggregate"但 H2 已有正确公式 | **覆盖度自检误报**（实测案例 5）：字面词映射（"写入"→write_range、"合计"→aggregate）不识别等价完成（add_formula 已覆盖两者语义） | 先按 3.14 核对日志"调用"记录：有 add_formula 真实调用且 H2 回读正确 → 是误报，任务实际成功，无需重跑 |
| 提示词被路由到 VBA 生成 | 提示词含"宏/脚本"字样 | 去掉宏相关词汇，保持"写入公式"表述 |
