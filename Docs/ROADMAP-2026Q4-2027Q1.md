## 2. 里程碑总览



```
M0 发布就绪（硬闸门）     10-28 → 11-21   能发、能装、能验
M1 商业闭环（营收开关）   11-22 → 12-19   能收钱、能激活、能退款
M2 质量加固（体验底线）   12-20 → 01-23   已知缺陷清零
M3 增长引擎（差异化）     01-24 → 03-底   扩大分发与付费转化
```

依赖链：M0 是 M1 的前置（无正式签名与公网服务端则支付链路无意义）；M1 的国内支付分支依赖公司商户资质（外部）；M2 与 M0/M1 可并行但优先承接 M1 上线后的用户反馈；M3 依赖 M0-M2 全部完成。

## 3. M0 发布就绪・硬闸门（10-28 → 11-21）

**目标**：在干净机器上可安装、可更新、无未知发布者警告、服务端可健康运行。



| 序 | 工作项                                                                     | 类型        | 验收标准                                                                              |
| - | ----------------------------------------------------------------------- | --------- | --------------------------------------------------------------------------------- |
| 1 | 采购并替换正式代码签名证书（EV 优先 / OV 备选）                                            | 外部依赖・最早启动 | vbproj `ManifestKeyFile`/`ManifestCertificateThumbprint` 更新；SmartScreen 无 "未知发布者" |
| 2 | 公网 HTTPS 发布目录 + 填 Excel/Word `InstallUrl`                               | 外部        | 已安装客户端可检测到新版本并升级                                                                  |
| 3 | `Legal/` 三件套主体替换（【运营方】→ 营业执照主体）并复核                                      | 人工        | EULA / PRIVACY / THIRD\_PARTY\_NOTICES 无占位                                        |
| 4 | LicenseServer 公网部署：`.env`（含强值 `ADMIN_ACTIVATE_KEY`）、`/health` 自检、密钥扫描出包 | 服务端       | `curl <域名>/health` 返回预期；`package-server.js` 产物无 .env/data/ 密钥                     |
| 5 | `release-check.ps1`（strict，不带 -Ci）全绿                                    | 闸门        | 退出码 0；证书 / 版本戳 / 一致性 /lint/ 测试 / 密钥边界全过                                           |
| 6 | 三宿主 Release 构建 + 重新出包（清除临时 pfx），版本号递增                                   | 交付        | dist 无 `_TemporaryKey.pfx`；`ApplicationVersion/Revision` 已递增                      |
| 7 | ClickOnce 更新链验证（V1 装 → V2 发 → 自动更新提示）                                   | 验证        | 干净机走通安装→更新→卸载                                                                     |

**M0 出口条件**：`Tools\release-check.ps1`（strict）全绿 + 干净机（无 Office 加载项残留）安装 / 更新 / 卸载通过。

## 8. 决策点（需要你在执行前拍板）



1. **签名证书预算**：EV（免 SmartScreen 警告，贵）还是 OV（便宜，首次可能弹警告）？—— 决定 M0 采购动作

2. **国内支付是否等公司主体**：若等，M1 先只上 Stripe + 人工激活码

3. **M3 的 Skill 扩展优先级**：6 个方向中先做哪 2 个（影响 2027-Q1 排期）

4. **是否需要把 git 纳入工作流**：当前机器 git 不在 PATH，无法本地查提交历史 / 分支管理（不影响构建，影响协作与回滚）
