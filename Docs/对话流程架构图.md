## 二、sendMessage() 完整调用流程

```
sendMessage(queuedMessage?)
│
├── [S0] 统一时间戳 sendTime = Date.now()
├── [S0] _acquireSendToken() → 获取令牌或入队
│   ├── 已有活跃令牌 → 消息入队 __sendQueue → return
│   └── 获取成功 → isSending=true, MY_TOKEN=时间戳
│
├── [S0] new SendContext({sendTime, queuedMessage, MY_TOKEN})
│   └── 集中管理: message, file, flags, DOM refs, 中间结果
│
├── [S0] _handleEditReplayCleanup()
│   └── 编辑重发: 移除被编辑消息及之后所有消息 + 清理工具记录
│
├── [S0] 停止残留 stream (currentStreamController.abort())
├── [S0] 转移 thinking-container 中的 streaming 消息到 chat-messages
├── [S0] 标记残留 streaming 消息为已完成 + 补充操作按钮
├── [S0] 隐藏欢迎面板
├── [S0] ensureMarkedLoaded() (确保 Markdown 渲染库已加载)
│
├── [S1] 读取输入
│   ├── input.value.trim() 或 queuedMessage
│   ├── 消息长度限制检查 (MAX=10000)
│   ├── 保存文件引用 (selectedFile / selectedFiles)
│   │   ├── 正常读取: previewVisible ? App.selectedFile : null
│   │   ├── 编辑重发恢复: recoverSelectedFiles()
│   │   └── 终极防御: fileInputEl.files + DOM 检测
│   ├── 清空输入框 + 显示用户气泡 addMessage('user', message)
│   └── 输入验证: hasAnyInput = message || file || files
│
├── [S2] 附件模式判断
│   ├── clearAttachment() 清空附件预览区
│   ├── hasAttachmentsOnly = 无聊天历史 + 有附件 + 无文本
│   │   ├── 有待处理图片技能 → 恢复消息进入Skill匹配
│   │   └── 否则 → 跳过Skill匹配，直接文件处理
│   └── 非纯附件模式 → 进入 matchAndExecuteSkillPipeline()
│       ├── shouldReturn=true → return (Skill已执行完毕)
│       └── recommendedSkill → 携带推荐Skill继续
│
├── [S5] skipAiFlow 检查
│   └── Skill已执行完毕 → return (进入finally)
│
├── [S6] 普通AI对话模式
│   ├── isProcessingImage 超时保护 (30s强制重置)
│   ├── API密钥检查 (providerConfig.needsKey && !apiKey)
│   ├── 身份证提取特殊路径 (extractIdCardFromText)
│   │
│   ├── 文件处理
│   │   ├── 多文件 → processMultipleFiles() → return
│   │   ├── 单文件 → _processSingleFileForSend()
│   │   │   ├── 文档文件 → DocumentProcessor.processDocument()
│   │   │   │   ├── Excel → buildExcelStructuredSummary()
│   │   │   │   ├── PDF/Word → 提取全文
│   │   │   │   └── 扫描版/空内容 → 提示使用OCR
│   │   │   ├── 图片文件 → fileToBase64() + 缩略图
│   │   │   └── 其他文件 → fileToBase64()
│   │   └── 图片后台准备 → quickAnalyzeImage() 预分析
│   │
│   ├── 模型选择: AUTO → getEffectiveModel() 解析
│   │
│   ├── 图片OCR路径 (hasImageContent && !isGenerateParseScript)
│   │   ├── SetOcrEngine('paddleocr') 强制本地引擎
│   │   ├── SaveBase64Image() → 保存图片到本地
│   │   ├── excel_ocr_recognize → MCP工具调用OCR
│   │   ├── OCR成功 → 构建OCR专用prompt → callAIStreamAndGetFullResponse()
│   │   │   └── prompt要求: <thinking>分析过程 + 结构化结果
│   │   └── OCR失败 → 显示错误消息 → return
│   │
│   ├── 提示词构建 (非图片路径)
│   │   ├── 图片内容 → imageAnalysisUnified prompt
│   │   ├── 文档内容 → documentAttachment prompt + 文件类型提示
│   │   └── 纯文本 → general prompt + Skill推荐 + VBA提示 + thinking强制规则
│   │
│   ├── MCP工具注入 → 可用工具列表追加到systemPrompt
│   │
│   ├── callAIStreamAndGetFullResponse(finalMessageContent, ...)
│   │   └── → 进入【流式响应处理流程】(见第四节)
│   │
│   ├── 图片分析后处理 _postProcessImageAnalysisResponse()
│   │   └── 检测推理式文本 → 折叠到"AI分析过程"
│   │
│   ├── 执行指令解析
│   │   ├── 标准格式: [EXECUTE:SkillName]
│   │   ├── 容错1: (SkillName)] 非标准括号
│   │   ├── 容错2: E:SkillName] 流式截断
│   │   └── 命中 → 清理显示 + setTimeout(500ms) → executeMatchedSkill()
│   │
│   └── 保存对话历史 + 更新上下文统计
│
├── [catch] 错误处理
│   ├── AbortError → 静默 (用户主动停止)
│   ├── availableSkills作用域问题 → 降级处理
│   └── 其他错误 → addMessage('ai', 错误信息)
│
└── [finally] 清理
    ├── 令牌释放: _activeSendToken = null
    ├── _releaseSendState(): isSending=false + resetSendButton
    ├── ctx.cleanup(): 重置所有标志位
    ├── fixedStatusBar.setIdle() 或显示队列数
    └── 队列自动发送: __sendQueue.shift() → sendMessage(nextItem)
```

## 三、文件处理路径详解

### 3.1 图片处理流程 (OCR 统一路径)

```
用户发送图片
│
├── fileToBase64() → base64Data
├── 用户气泡追加缩略图 updateLastUserMessage(imageThumbnailHtml)
│
├── SetOcrEngine('paddleocr') → 强制本地OCR引擎
│
├── SaveBase64Image(base64Data, fileName)
│   ├── WebView2 Bridge 直调 (优先)
│   └── HTTP API fallback (http://localhost:9527)
│
├── excel_ocr_recognize(imagePath) → MCP工具调用
│   ├── 成功: ocrResultStr (识别文字)
│   └── 失败: ocrError → 显示错误 → return
│
├── 构建OCR专用系统提示词
│   ├── 要求 <thinking> 标签输出分析过程
│   ├── 要求 Markdown 结构化结果
│   └── 附加 OCR 结果文本
│
├── callAIStreamAndGetFullResponse(ocrPrompt)
│   └── AI 分析 OCR 结果 → 流式渲染
│
└── 完成后: _releaseSendState() → return
```

### 3.2 文档处理流程

```
用户发送文档 (xls/xlsx/doc/docx/pdf/ppt/pptx/txt/csv)
│
├── DocumentProcessor.processDocument(file)
│   ├── onProgress 回调 → 更新状态栏
│   ├── Excel → 解析工作表 + buildExcelStructuredSummary()
│   ├── PDF → 提取文本 (扫描版检测)
│   └── Word → 提取段落和表格
│
├── 解析结果处理
│   ├── 扫描版/空内容 → 提示使用OCR
│   ├── 仅文件路径 → 提示上传实际内容
│   └── 正常内容 → 构建 <document> XML标签
│
├── 用户气泡追加文档信息卡片
│
└── 将文档文本附加到消息内容 → 发送给AI
```

### 3.3 多文件批量处理

```
用户发送多个文件
│
├── processMultipleFiles(message, files)
│   ├── 逐一解析每个文件
│   ├── 智能分析流程
│   └── 合并结果展示
│
└── _releaseSendState() → return
```

## 四、AI 调用与流式响应处理

### 4.1 callAIStreamAndGetFullResponse() 调用链

```
callAIStreamAndGetFullResponse(message, imageBase64, loadingMsgId, ...)
│
├── ContextManager.buildContext(message, imageBase64)
│   ├── getCleanHistory() → 获取清理后的对话历史
│   ├── 构建 messages[] 数组 (system + history + user)
│   └── 注入工作簿上下文 (isOpenWorkbooksQuestion)
│
├── createStreamingMessage() → 创建流式消息DOM
│   ├── wrapper.message-wrapper.ai.streaming
│   ├── header: 提供商 + 模型名 + 时间
│   └── messageDiv: typing-indicator (豆包风格加载态)
│
├── removeAIThinkingStatus(loadingMsgId) → 移除加载指示器
│
├── callAIUnified({messages, stream: true, model, ...})
│   ├── 构建 AbortController → currentStreamController
│   ├── fetch() SSE 流式请求
│   └── 返回 Response 对象
│
├── 流式读取循环 (reader.read())
│   ├── 解析 SSE data: 行
│   ├── JSON.parse → delta.content / delta.thinking
│   ├── 安全校验: 对明确 <thinking> 标签跳过
│   └── 路由到对应分支 (见 4.2)
│
├── [D-7] MCP tool_calls 处理
│   ├── 检测 tool_calls → 执行工具 → 二次调用AI
│   ├── TimelineRenderer 追加工具步骤
│   └── 结果渲染到时间线
│
├── [D-7b] 方括号工具调用检测
│   └── [tool_name]{args} 格式 → 执行 → 同上
│
├── [D-5] 最终渲染
│   ├── 提取 fullThinking + fullContent
│   ├── 检查已有 .thinking-live-wrapper → 跳过重复
│   ├── renderThinkingSection() (如果有thinking)
│   └── renderMessageContent() (最终内容)
│
├── finalizeStreamingMessage(elements, fullContent)
│   ├── 清理临时消息 (thinking-only, streaming)
│   ├── 更新 badge: "任务决策中" → "任务决策"
│   ├── 添加操作按钮 (复制/重新生成/点赞/踩)
│   ├── Markdown 最终渲染
│   └── 动画 + 滚动到底部
│
└── return fullContent
```

### 4.2 流式分支路由 (D 分支体系)

```
每个 SSE chunk 到达时:
│
├── content 字段有值
│   │
│   ├── [D-2] 检测到 <thinking> 开始标签
│   │   └── 进入思考模式: 累加到 fullThinking
│   │       └── 流式渲染: thinking-live-wrapper (实时更新)
│   │
│   ├── [D-2] </thinking> 闭合标签检测到
│   │   └── 思考完成: 分离 thinking + content
│   │       ├── 已有 _liveWrapper → 更新 badge + body + 追加 content
│   │       └── 无 _liveWrapper → 创建新 section
│   │
│   ├── [D-2] 有 fullThinking (原生 thinking 字段)
│   │   └── [D-1] 完整步骤HTML模板
│   │       ├── 已有 _liveWrapper → 更新
│   │       └── 无 → 创建
│   │
│   └── [D-2] 无 thinking
│       └── 纯文本 Markdown 渲染 → updateStreamingMessage()
│
├── thinking 字段有值 (Ollama 原生 thinking)
│   │
│   ├── [D-3] 无 content → 流式思考模板 (thinking-live-wrapper)
│   │
│   ├── [D-3b] 有 content → 思考 + 内容同时显示
│   │   ├── 已有 _liveWrapper → 更新
│   │   └── 无 → 创建
│   │
│   └── [D-4] 思考模式关闭 → "AI 正在分析中" 占位
│
└── tool_calls 有值
    └── [D-7] MCP 工具执行流程
```

```
executeMatchedSkill(skillMatch, message)
│
├── 并发防护: skillName锁 + 防抖 (800ms)

├── 路由到具体执行器

│   ├── SkillCreator → executeSkillCreator()
│   │
│   ├── 通用Skill (isGeneric) → executeCustomSkill()

│   └── VBA Skill (默认)
│       └── executeVBASkill(skillName)
│
└── finally: 释放锁 + 清理 _currentSkillConfig
```

## 六、UI 渲染机制

### 6.1 流式消息 DOM 结构

```
message-wrapper.ai.streaming
├── message-avatar.ai (头像)
└── message-content
    ├── message-header
    │   ├── 提供商名称
    │   ├── model-badge (模型名)
    │   ├── message-time (时间)
    │   └── streaming-indicator (● 脉冲)
    └── message.ai.streaming-content
        ├── typing-indicator (加载动画)
        ├── message-main
        │   ├── streaming-live-area (流式内容区)
        │   │   ├── thinking-live-wrapper (思考过程)
        │   │   │   ├── thinking-process
        │   │   │   │   ├── thinking-header → thinking-badge
        │   │   │   │   └── thinking-body (步骤列表)
        │   │   │   └── streaming-content (最终内容)
        │   │   └── ... 增量更新内容
        │   └── timeline-container (工具执行时间线)
        └── process-log (步骤日志)
```

### 6.2 关键 UI 更新函数

```
createStreamingMessage()
  → 创建 wrapper + header + messageDiv + typing-indicator
  → startPulse(wrapper) 初始态脉冲

updateStreamingMessage(elements, content)
  → 50ms 节流 + 增量渲染优化
  → HTML内容: innerHTML 直接替换
  → Markdown: renderMessageContent() 渲染
  → 增量追加: 检测前缀相同 → 只追加差异部分
  → animateMessage() 动画 + scrollTop 自动滚动

finalizeStreamingMessage(elements, fullContent)
  → 清理临时消息
  → badge 更新: "任务决策中" → "任务决策"
  → createMessageActions() 添加操作按钮
  → 最终 Markdown 渲染
  → stopPulse() + animateMessage() 完成动画
```

## 七、状态管理

### 7.1 全局状态变量

```
┌──────────────────────────┬───────────────────┬──────────────────────┐
│ 变量                     │ 类型              │ 用途                 │
├──────────────────────────┼───────────────────┼──────────────────────┤
```

## 十、错误处理与容错机制

```
┌─────────────────────────────────────────────────────────────────────┐
│                        错误处理层级                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  1. 令牌过期保护                                                     │
│     └── 令牌年龄 > 30s → 强制回收 + 释放发送状态                     │
│                                                                     │
│  2. 图片处理超时                                                     │
│     └── isProcessingImage > 30s → 强制重置                           │
│                                                                     │
│  3. Skill执行超时                                                    │
│     └── Promise.race([skillExec, 60s timeout])                       │
│     └── SkillCreator: 240s timeout                                  │
│                                                                     │
│  4. 流式中断恢复                                                     │
│     └── AbortError → 静默处理 (用户主动停止)                         │
│     └── 网络错误 → addMessage('ai', 错误信息)                        │
│                                                                     │
│  5. 文件恢复防御                                                     │
│     └── 三级防御: App.selectedFile → backupSelectedFile              │
│                  → fileInputEl.files → DOM检测                       │
│                                                                     │
│  6. OCR失败降级                                                      │
│     └── OCR失败 → 显示错误消息 (不崩溃)                              │
│                                                                     │
│  7. AI调用失败                                                       │
│     └── 错误详情 + 可能原因 + 建议操作                                │
│                                                                     │
│  8. 队列溢出保护                                                     │
│     └── __sendQueue.length > 3 → shift() 丢弃最早消息               │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```
