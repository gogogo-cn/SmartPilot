# 退款 SOP：消 key 退款

离线激活码（`SPK1-…`）在 .NET 侧本地验签，**服务端无法远程吊销**。所以退款走「先消 key、再放款」：

```
用户点「注销并申请退款」
   → 本机激活被清除 + 该 key 在本机永久失效
   → 客户端生成「消 key 码」SPD1-…
   → 用户把码发给客服
   → 运营台验签 + 定位台账 + 查重
   → 确认退款（同时写入吊销名单）
```

关键点：**退款与失效是同一个动作的两面**，不依赖用户联网。

---

## 零、这套流程不需要服务器

整条商业闭环全部在本机完成 —— **LicenseServer 不作为服务运行时，下面每一环照常工作**：

| 环节 | 在哪完成 | 需要服务器吗 |
|---|---|---|
| 生成激活码 | 本地 CLI（`LicenseServer/lib/licenseKey.js`，纯 `crypto`） | 否 |
| 验签 / 判定有效期 | 客户端 VB 本地 HMAC | 否 |
| 生成消 key 码 | 客户端 VB 本地 | 否 |
| 验证消 key 码 | 运营台本地 Node（把 `licenseKey.js` 当**库**用，不起服务） | 否 |
| 标记退款 / 写吊销名单 | 运营台写本地 CSV / JSON | 否 |
| 前端门禁判定 | `license.js` 先查本地激活，命中即放行 | 否 |

服务器（`node LicenseServer/server.js`）只是**可选增强**，只用于：在线账号订阅、Stripe / 微信 / 支付宝自动发货、吊销名单下发。**它挂了、或压根不部署，上表全部不受影响。**

> ⚠️ 「不需要服务器」**不等于**可以删掉 `LicenseServer/` 目录。
> 该目录的 `lib/licenseKey.js` 是 Excel / Word / PPT / 运营台三端共用算法的**唯一来源**，
> `data/issued-keys.csv` 是激活码**权威台账**。它只是**不当服务启动**，不是没用。
> 运营台已加启动预检：误删会给出上面这段说明，而不是崩在 `MODULE_NOT_FOUND`。

守栏：`Tests/no-server-required.test.js`（7 条）—— 把 `http / https / net / dns / fetch` 全部毒化后，
「发码 → 销码 → 验码 → 退款 → 写吊销名单」仍必须完整跑通。谁在链路上加了联网调用，测试立刻红。

## 一、客户端（用户侧）

1. 打开「账户 / 订阅」→ 激活码区
2. 点 **注销并申请退款**（仅在已激活时可见）
3. 确认提示后：本机立即失去授权，界面显示 **消 key 码**
4. 点复制，发给客服

注销后：

- 这台机器立刻回到未授权状态
- **同一张激活码在本机不能再被激活**（`ActivateKey` 会查已注销名单）
- 即使手工恢复激活记录也会被拦（`GetLocalActivation` 同样会查）

> 统一激活门禁（2026-10-21 定型）：激活记录的唯一存储是共享会话
> `%APPDATA%\SmartPilotOffice\license_session.json`（DPAPI 保护），Excel / Word / PPT
> 共用同一份激活与同一份注销名单。因此**在任意一端注销，所有端同时失效**；
> 旧版 Excel 曾把激活记在自己的 ConfigurationManager 里（双轨），现已降级为
> 「迁移源」——首次读取时自动搬进共享会话，此后三端同源。守栏测试：
> `Tests/license-shared-gate.test.js`。

## 一点五、多席位订单：必须「每人一码」（2026-10-21 定）

**规则**：买几个席位就生成几张**独立激活码**（每张 `seats=1`），绝不共用一张写 `seats=N` 的码。

原因：

- 共用一张码时，团队里任一人退款 → 你只能吊销那唯一一张 key → **全队连坐失效**
- 一客一码时，谁退就注销谁的，**其他人无感**；台账每人一条，售后/查到期/补发都可追溯
- 两边总价相同：`¥99 × 人数`（5 人 = ¥495；2026-10-21 由 ¥599 调为 ¥99，原价是个人年付 3 倍且无量折扣）

运营台操作：方案选「团队版 · 按席位」，在 **席位 / 人数** 填 5 → 「生成数量」自动联动为 5 → 提交即得 5 张互异的 key（`login` 自动加 `+1…+5` 后缀；若要每人各自邮箱，请逐人分别生成）。

> 补充事实：激活码本身**不校验收发台数**（离线验签只看签名和有效期），所以"席位数"是账目口径而非技术限制。想技术上限制席位数必须引入在线激活/心跳，那会否掉"不需要服务器"这个前提。

## 二、运营台（你这边）

```bash
node OpsConsole/server.js     # http://127.0.0.1:9600
```

1. 切到 **消key退款** 页签
2. 粘贴用户发来的 `SPD1-…`，点 **验证注销码**
3. 看到客户 / 套餐 / 到期 / 本机销毁时间，核对无误
4. 点 **确认退款（同时吊销该激活码）**

系统会自动做三件事：

| 动作 | 效果 |
|---|---|
| 标记 `refunded` | 不计入销售额统计，记 `refundedAt` |
| 写入吊销名单 | `LicenseServer/data/revoked.json`，只存 `SHA256(key)` 前 16 位 |
| 防重复退款 | 已退过款的码会被拒绝 |

## 三、为什么要吊销名单（兜底）

用户在本机注销**只让那台机器**失效。如果他事先备份了激活码，换一台机器仍能激活。
退款后写入吊销名单，联网客户端拉到名单即可拦住。

- 公开接口：`GET /api/revoked`（只含哈希，不含激活码原文，可公开）
- 单码查询：`GET /api/license/verify?h=<16位哈希>`
- 管理接口：`POST /api/admin/revoke`、`/api/admin/unrevoke`（`X-Admin-Key` 守护）

## 四、安全属性（已单测覆盖）

- 消 key 码**不含激活码原文**，经微信/邮件外传也安全
- 伪码/篡改一律拒绝：`bad_signature` → 提示「不要退款」
- 非本系统签发的码：台账查不到 → 拒绝
- 同一张码不能退两次

## 五、已知边界

1. **纯离线用户不会被吊销名单拦住**——但他在申请退款时已经在本机消过 key，所以本来就已失效。风险只在于"备份 + 换机 + 永不联网"这一组合。
2. 离线激活的 HMAC secret 在客户端 DLL 中（离线验签的固有取舍），理论上可被逆向自造激活码。消 key 机制属于"防君子"级别的商业闭环，不是密码学强保证。
3. 注销**不可逆**。用户若反悔，需重新购买。
