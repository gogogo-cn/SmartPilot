## 二、关键结论（Top 5）

1. **PPT 多元风格体系已真实落地**：8 主题 × 5 风格方向 × 13 种版式 + WCAG 校验 + 模板主题导入 + 图片取色——这正是你上一轮问的"多元风格 AST 能力"的已实现版本，路线正确。
2. **无版本控制（无 .git 目录）＝ 当前第一风险**：没有历史回滚、没有备份基线，且已有的 .github/workflows 完全无法触发。

5. **稳定性工程亮点多**：关闭链路分步监控、OCR 独立进程、COM 释放工具类、VBA 沙箱——这些是长期沉淀的好资产，重构时不要推倒重来。

## 三、问题清单（按优先级，附证据）

### P0 — 阻断级

**P0-1 项目无版本控制**
- 证据：项目目录无 `.git`（实测）；`.github/workflows/build.yml` 依赖 push 触发，无仓库则永不执行。
- 影响：无法回滚、无法分支、无备份基线；一旦误删文件或改坏无法恢复；CI 形同虚设。
- 修复：`git init` → 清理残留（P1-3）→ 补 .gitignore → 首次提交 → 推私有远端（GitHub/Gitee）。**今天做**。

### P1 — 高危

**P1-1 PPT 生成同步阻塞 Excel UI**
- 证据：`PptGenerationService.vb:775` 在 Excel 进程内 `CreateObject("PowerPoint.Application")`；`PptGenerationService.vb:447` `Generate()` 为同步静态方法 + `Monitor.TryEnter` 并发锁；`ExcelBridge.vb:1524` `GeneratePPTFromData` 为 ComVisible 前端入口（WebView2 JS 调用 → Excel 主线程 STA 执行）。
- 影响：生成几十页 PPT + 图表时（数秒~数十秒）Excel 窗口无响应；PowerPoint 缺失/损坏/WPS 环境直接抛错无降级。
- 修复方向（不推翻现有引擎）：
  1. 提交式任务：`Generate` 改为返回 `taskId`，后台线程执行，前端轮询或 SSE 拿进度（项目已有 `SseParser.vb`、`StreamPushService.vb` 可复用）；
  2. 生成前探测 PowerPoint 可用性并给前置提示；
  3. 中期：将生成核心下沉到独立进程/服务（OcrHost 同款模式），Excel 只发数据快照。

**P1-2 `RunOnUIThread` 异常分支双重执行**
- 证据：`ThisAddIn.vb:83-89` —— `Try action() Catch : action() : End Try`，第一次调用抛异常后直接重跑 action，吞掉原始异常；若 action 有副作用（弹窗/写文件/写单元格）会执行两次。
- 修复：改为 `Catch ex` 记录日志并重新抛出（或仅回退一次并告警），不得静默双重执行。

**P1-3 仓库卫生：调试残留未纳入 .gitignore**
- 证据（根目录实测）：
  - `da.yml / db.yml / va.yml / vb.yml / fd.yml / ga.yml / gb.yml / find-plan.yml / find-spk.yml / mcp1.yml / ocr_final.yml / ocr_main.yml / ocr_panel2.yml`（13 个，28B~5.8K）
  - `_tmp_panel.png / _tmp_sheet.png / _tmp_summary.png`
  - `.playwright-cli/`（20+ console-*.log / page-*.yml 快照）
  - `.codebuddy/`、`.trae/`（含 rules/documents/skills）、`.workbuddy/memory`、`.trae-html-share-packages/`（多个 AI 助手目录混入仓库根）
  - `Services\__pycache__`、`Tools\__pycache__`、`Tests\__pycache__`、`Hosts\Shared\Config\__pycache__`、`StandaloneAgent\__pycache__`
- 影响：git init 后这些全部入库，仓库爆炸且包含可能泄露的调试信息。
- 修复：先清理，再在 .gitignore 追加：`.playwright-cli/`、根目录 `*.yml`、`_tmp_*.png`、`.codebuddy/`、`.trae/`、`.workbuddy/`、`.trae-html-share-packages/`、`**/__pycache__/`。

**P1-4 默认启用的高权限 MCP**
- 证据：`Config/mcp.json:8-19` —— `filesystem`（`args` 含 `%USERPROFILE%`，全用户目录读写）与 `ms365`（Graph API 访问邮件/日历/OneDrive/Excel）均 `enabled: true`。
- 影响：LLM 工具面 = 用户整个家目录 + 微软账号数据。个人使用尚可，商业化分发风险极高。
- 修复：默认 `enabled: false`，用户按需在 `mcp.user.json` 显式开启；分发前做权限面声明。

### P2 — 中

**P2-1 Option Strict 不一致**
- 证据：`ExcelAIVSTOAddIn.vbproj:989` 为 On；但 `PptGenerationService.vb:12`、`Hosts\PptAIVSTOAddIn\Connect.vb:11` 文件级 Off（覆盖项目级），`Core\SmartPilot.Core.vbproj:238`、`OcrHost\OcrHost.vbproj:18`、`WordAIVSTOAddIn.vbproj:217` 均 Off。
- 影响：后期绑定/拼写错误运行时才炸；三宿主+核心库行为不一致。
- 修复：COM 后期绑定收敛到最小范围（局部 `LateBinding` 或强类型 Interop 程序集），纯逻辑文件恢复 Strict。**注意：PptGenerationService 内大量 COM 后期绑定调用是刻意的，不要一刀切，按文件评估。**

**P2-2 测试工程目标框架与主工程不一致**
- 证据：`Tests\VbTests\*.vbproj:5` 为 `net10.0`，主工程 v4.7.2。CI 中 `dotnet run` 测试工程（build.yml:195），依赖"共享源文件模式"保持 COM-free。
- 影响：可运行但脆弱——被测类一旦引用 Office/COM 依赖即断链；测试与主工程编译隔离。
- 修复：纯逻辑类继续下沉到 `Core\SmartPilot.Core`（已是独立工程），主工程只保留宿主薄层；这也正是后续"独立 SkillHost/服务化"演进的基础。

**P2-3 启动写 %TEMP% 固定文件名**
- 证据：`ThisAddIn.Startup.vb:24` 写 `%TEMP%\addin_path.log`（固定名）。
- 影响：多实例/多用户冲突、写临时目录不卫生。
- 修复：归入 `AppLogger` 统一日志目录。

**P2-4 过时注释误导**
- 证据：`PptGenerationService.vb:7` 注释"固定商务蓝主题"，实际已为 8 主题 JSON 驱动（ppt_templates.json + custom_ppt_themes.json 合并）。
- 修复：更新注释，避免后续维护者误判。
